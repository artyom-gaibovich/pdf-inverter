## Context

Репозиторий новый: кода приложения ещё нет. Задача — клиентское SPA без бэкенда (см. proposal.md — Why). Ключевые ограничения: вся обработка PDF в браузере, публикация на GitHub Pages (статика, работа из подкаталога `/<repo>/`).

Технически инверсия строится на растеризации: PDF.js рендерит страницу на `<canvas>`, дальше пиксели инвертируются, а из готовых изображений собирается новый PDF. Векторный/текстовый слой при этом не сохраняется — это осознанный компромисс ради простоты (пользователь выбрал простую инверсию).

## Goals / Non-Goals

**Goals:**

- React + Vite SPA, разворачиваемое на GitHub Pages одним workflow.
- Загрузка PDF, опциональная нарезка по диапазону страниц, простая попиксельная инверсия, экспорт нового PDF.
- Отзывчивый UI с индикацией прогресса для многостраничных файлов.

**Non-Goals:**

- Сохранение текстового/векторного слоя в результате (страницы растрируются).
- «Умная» инверсия (hue-rotate, щадящая обработка фото) — вне объёма.
- Встроенный просмотрщик-читалка с постраничной навигацией (только обработка и скачивание; предпросмотр опционален).
- OCR, распознавание, сжатие результата.

## Decisions

**Рендер PDF: `pdfjs-dist` (PDF.js).**
Де-факто стандарт для рендера PDF в браузере, надёжный парсинг. Альтернатива — рендер силами `pdf-lib` — отпадает: `pdf-lib` не растеризует страницы. Воркер PDF.js подключаем как статический ассет Vite, путь к воркеру задаём через `GlobalWorkerOptions.workerSrc` с учётом `import.meta.env.BASE_URL`, чтобы работало из подкаталога Pages.

**Инверсия: попиксельно на canvas (`ImageData`, `255 - value` по RGB, alpha без изменений).**
Простой и предсказуемый результат, совпадает с выбором пользователя. Рендерим на нужном масштабе (devicePixelRatio/scale ≈ 2) ради читаемости растра. CSS-фильтр `invert(1)` отвергнут: он инвертирует только отображение, но не даёт данных для экспорта в файл.

**Сборка PDF: `pdf-lib`.**
Даёт контроль над размером страниц и встраиванием изображений (`embedJpg`/`embedPng`), активно поддерживается. Инвертированный canvas экспортируем в JPEG (меньше размер) или PNG (без потерь) и вставляем как полностраничное изображение с сохранением исходных пропорций. Альтернатива `jsPDF` проще, но `pdf-lib` удобнее для покомпонентной сборки и контроля размеров.

**Нарезка страниц.**
Диапазон [N, M] применяется до рендера: обрабатываем и включаем в результат только страницы N..M. Валидация против фактического `numPages`, полученного из PDF.js. Пустой диапазон = весь документ.

**Производительность и UI.**
Обработка последовательная, постранично, с обновлением прогресса. Тяжёлый рендер держим в основном потоке на первой версии; вынос в Web Worker — возможная последующая оптимизация (не в объёме). Для очень больших файлов ограничение — память браузера (см. Risks).

**Деплой: GitHub Actions + GitHub Pages (`actions/deploy-pages`).**
Официальный путь публикации статики. В `vite.config` задаём `base: '/<repo>/'`. Workflow: `checkout` → `setup-node` → `npm ci` → `npm run build` → `upload-pages-artifact` → `deploy-pages`. Триггер — push в основную ветку.

## Risks / Trade-offs

- **Растеризация теряет текстовый слой** → осознанный компромисс; фиксируем в README как известное ограничение. Экспорт в JPEG для контроля размера файла.
- **Память браузера на больших PDF** → обрабатываем постранично, освобождаем canvas/ImageData между страницами; для крупных файлов рекомендуем нарезку диапазоном.
- **Путь воркера PDF.js ломается на Pages (подкаталог)** → используем `BASE_URL` и проверяем сборку на URL вида `/<repo>/`.
- **Размытость растра при низком масштабе** → рендерим со scale ≥ 2; при желании настраиваемый DPI (вне первого объёма).
- **Первый деплой требует включения Pages в настройках репозитория (source = GitHub Actions)** → фиксируем шаг в README.
